# Competency Hub

Competency Hub has four sections: My Competency, Team Capability, Competency Matrix, and Reports & Insights. The current interface analyzes projects and tasks; it does not require a separate assessment.

The Performance Index combines available delivery reliability, work quality and correction-response measurements. The Competency Index separately combines available quality, problem solving, correction ownership and knowledge sharing. Admin can configure the weights, response-time target, sharing target and required capability level inside Competency Hub. Each result shows its inputs and calculation coverage. Missing observations are excluded, never invented or treated as zero. The interface uses Waiting for completed work when no usable work exists.

Work inputs include completed development and quality/release events, preserved planned dates, correction cycles, assigned issues and their resolutions, linked testing results with actual recorded scores, published contributions and short approval/completion feedback. A completed testing run is not a passing test. Unlinked tests remain independent and do not enter project-based scores. Raw iteration/error counts alone do not create proficiency scores.

Approval and completion offer three short questions about correction needs, problem solving and follow-through. Optional fields record corrected errors, solved troubleshooting cases, additional sharing outside TechShare, colleagues helped and a comment. The authorized workflow actor records these answers for the engineer who completed the work. Attribution is captured on the action. Repeated quality/release entries update that work item's recorded answers rather than multiplying its contribution count.

The derived work capability level uses 1 + 4 x measured dimension / 100. It is an operational work indicator, not a separate claim of specialist certification. Delivery and feedback records remain available when a score is expanded. Existing assessment records, approvals, permissions, development goals and legacy APIs are retained; they are not silently converted into project outcomes.

Insight layouts are personal. Users can add, edit, reorder and remove metrics, titles and notes, and choose cards, bars, lines, areas, pies, donuts, radar, gauges, heatmaps, tables or delivery trends. Charts require actual values. Trends show each recorded work outcome by its review/completion date. Reports expand before download and PDF/Excel use the same work calculations and feedback as the dashboard.

The project selector has a separate blue background. Record results for this project is checked by default. With no valid project selected the tool sends the explicit independent-test marker and continues testing. Selecting an assigned project links subsequent results to that project and their recorded author. Changing the selector later cannot rewrite a completed run's attribution.

Explicitly fictional sample projects are excluded from real employee indices. Selecting a sample project opens a labelled sample preview; its reports carry SAMPLE PREVIEW in the title.
