# e-design tools, split sidebar and review front page

Implemented and verified on 2 November 2026.

The drawing-tool selector now includes Cloud + arrow + comment, Revision cloud only, Highlight + comment, Underline, Freehand marker, Rectangle + comment, Arrow and Comment pin. The toolbar picks the colour for new marks. Selected-mark properties edit colour and opacity. Highlighters are translucent and freehand markers retain normalized stroke points. Cloud-only, highlight, underline and marker tools can be saved without text; comments can be added later against their reference. Clouds with comment boxes remain the default drawing mode. Arrowheads now use a small fixed drawing-space marker rather than multiplying their size by stroke width.

Reference numbers are allocated and stored in the review database, rather than calculated from a filtered list index. Existing records receive numbers in their previous page/creation order, including retained deleted records. New references do not reuse deleted numbers; edits, page changes, filtering, Undo/Redo and restores retain a mark's identity. All export formats use the saved references. Native review PDFs include grouped reference labels as well as editable markup annotations.

The sidebar has two panels: comments above and properties below. Each scrolls independently. Its divider and desktop sidebar width support pointer dragging and keyboard adjustment, with account-scoped saved dimensions. Narrow windows place the sidebar below the drawing. The comment list searches reference, text and author; filters cover current/all pages and All/Open/Resolved states. Selecting a comment opens the corresponding properties below. Revision history remains available in the properties panel.

The existing Export menu opens a review front-page dialog for PDF, PDF correction report, Word and HTML. It prefills the drawing filename, current reviewer, available assigned reviewers, date, description and initial review version. Users can edit those fields plus review sign-off, approved-by, approval date and approval details. Approval and sign-off fields start blank. Front-page edits are stored with their own conflict-checked version history. View-only recipients can export saved/default details and cannot change the saved front page. CSV remains a comment table.

PDF front pages are kept separate from drawing page numbers in the portable envelope. Reimporting a covered PDF strips its front page from drawing previews, retains review metadata, and does not shift comments or accumulate covers on subsequent exports. Original uploaded PDFs remain unchanged. The legacy GET export API retains its original behavior unless `include_cover=true`; the current UI always includes the front page for document exports.

Verification: **29 backend tests passed** across existing e-design persistence, permissions, geometry, undo/redo and portable-PDF checks, plus new drawing tools, colours, stable references, cover conflicts, covered-PDF import/export and all document formats. The browser exercised all new tool types, colour/stroke persistence, cloud-only behavior, reference search, Open/Resolved filters, independent scrolling, pointer/keyboard split and width adjustments, small arrowheads, editable prefilled cover export, and light/dark layouts at 1800, 900 and 390 CSS pixels. Browser PDF inspection confirmed the front page and the original two drawing pages. All three production interfaces built successfully.
